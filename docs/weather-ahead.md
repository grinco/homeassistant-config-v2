# Weather ahead: the tower picture on Home

*2026-11-11.*

## What it is for

One look at Home should say how to dress. The Weather section now sits at the top of Home, and
the stock `weather-forecast` card there (current conditions and the daily forecast) has a
picture of the Žižkov television tower as its background, in the weather of the **next three
hours**, by day or by night.

It is one card on purpose. A separate picture card above the forecast was tried first and
rejected by the operator: the tower is meant to be part of the weather card.

The picture shows the worst of the next three hours, not the current weather: if it is dry
now and rain arrives in two hours, the picture shows rain.

## Pieces

| piece | where | what |
|---|---|---|
| `weather_ahead` macro | `custom_templates/weather_ahead.jinja` | reduces an hourly forecast to the worst condition, its scene, day/night and the dressing numbers |
| `sensor.weather_ahead` | `configuration.yaml`, trigger-based `template:` | calls `weather.get_forecasts` (hourly) every 15 min, on start, on template reload and on a `weather.home` state change; state = the condition, attributes = the rest |
| scene images | `/config/www/zizkov/<scene>-<day\|night>.jpg` | 10 scenes × day/night, generated by `tools/weather-scenes/` |
| background | Home, the `weather-forecast` card in the Weather section | `card_mod` style: the scene image under a top and bottom scrim, white text |
| tests | `tests/weather/` | `run.py` checks the deployed macro, and `mutate.py` confirms the cases catch bugs |

### Why a template sensor and not a native helper

No helper reads a forecast: since 2024.3 forecasts are only available through the
`weather.get_forecasts` action, and only a trigger-based template entity can call an action
and keep the response. That also rules out a UI template helper: the config flow has no field
for triggers, actions or attributes. The reduction is a macro rather than inline Jinja, so the
tests call the same code the sensor runs.

### The rules the macro implements

- **Window:** the hour in progress through the last hour that *starts* before now + 3 h. At
  10:30 that is 10:00–13:00. The 14:00 hour is out.
- **Worst condition:** what changes what you wear outranks what does not. From the top:
  thunderstorm, thunder, hail, pouring, snow, sleet, rain, wind, fog, cloudy, exceptional,
  partly cloudy, sunny/clear. On a tie the earlier hour wins.
- **Scene:** the 15 HA conditions map onto 10 pictures: sunny, partlycloudy, cloudy, rainy,
  pouring (also hail), storm (lightning, lightning-rainy), snowy, sleet (snowy-rainy), fog,
  windy (windy, windy-variant). clear-night is the sunny scene at night, and exceptional is
  cloudy.
- **Day or night:** `is_daytime` of the hour in progress, falling back to `sun.sun`.
- **Numbers, over the window only:** temperature min/max, feels-like minimum, precipitation
  sum, highest precipitation probability and highest wind speed.
- **No forecast** (integration down): the macro returns `{}` and the sensor goes
  unavailable. The card then shows the cloudy picture, day or night from `sun.sun`.

### Two traps in the sensor, both silent

Both left the sensor `unavailable` with nothing in the log:

- **A top-level `variables:` in a trigger template is rendered before `actions:` run.** At
  that point the forecast response `fc` does not exist yet. The reduction therefore runs in a
  `variables` step *inside* `actions`, after `weather.get_forecasts`.
- **A template result becomes a dict only if it reads as a Python literal.** The macro
  returns JSON, and JSON's `true`, `false` and `null` are not Python, so the variable stayed a
  string and `ahead.condition` was undefined. `| from_json` in the variable fixes it.

## The pictures

They are drawn, not photographed. One public-domain photo of the tower against a clear
blue sky ([Wikimedia Commons, "Zizkov tv tower.jpg"](https://commons.wikimedia.org/wiki/File:Zizkov_tv_tower.jpg),
by Orange.man) is cut out of its sky, and `scenes.py` paints each scene around it: sky,
sun or moon and stars, clouds, rain, snow, a lightning bolt, wind streaks and fog. The tower
is relit for each scene, and at night the red obstruction light on the antenna is on.

```bash
python3 tools/weather-scenes/cutout.py src.jpg tower.png 12   # 12 = how far the sky fill may grow
python3 tools/weather-scenes/scenes.py tower.png out/ 900x620 0.5   # size, tower centre
sudo install -m 644 out/*.jpg /usr/share/hassio/homeassistant/www/zizkov/
```

The image URL carries `?v=2`. After regenerating the images, bump it: `/local/` is cached
for 31 days.

## Not covered by a test

- That the sensor fires and the action returns a forecast: checked by reading
  `sensor.weather_ahead` back after deployment.
- How the card looks: checked by rendering Home at 390 px and 1280 px with
  `tests/dashboards/render.py`. The scene images are 900×620 with the tower centred, which
  suits the forecast card's shape. The text sits over the darker top and bottom of the
  picture.

## Configuration as deployed

`configuration.yaml`:

```yaml
template:
  - triggers:
      - trigger: time_pattern
        minutes: "/15"
      - trigger: homeassistant
        event: start
      - trigger: event
        event_type: event_template_reloaded
      - trigger: state
        entity_id: weather.home
        to: ~
    actions:
      - action: weather.get_forecasts
        continue_on_error: true
        target:
          entity_id: weather.home
        data:
          type: hourly
        response_variable: fc
      - variables:
          ahead: >-
            {% from 'weather_ahead.jinja' import weather_ahead %}
            {% set rows = fc['weather.home'].forecast if fc is defined and 'weather.home' in fc else [] %}
            {{ weather_ahead(rows, now()) | from_json }}
    sensor:
      - name: Weather ahead
        unique_id: weather_ahead_3h
        icon: mdi:weather-cloudy-clock
        availability: "{{ ahead.condition is defined }}"
        state: "{{ ahead.condition }}"
        attributes:
          scene: "{{ ahead.scene }}"
          daytime: "{{ ahead.daytime }}"
          temp_min: "{{ ahead.temp_min }}"
          temp_max: "{{ ahead.temp_max }}"
          feels_min: "{{ ahead.feels_min }}"
          precipitation: "{{ ahead.precip }}"
          precipitation_probability: "{{ ahead.precip_prob }}"
          wind_max: "{{ ahead.wind_max }}"
```

The weather card on Home:

```yaml
type: weather-forecast
entity: weather.home
forecast_type: daily
show_current: true
show_forecast: true
card_mod:
  style: |
    {% set a = states.sensor.weather_ahead.attributes if states.sensor.weather_ahead is not none else {} %}
    {% set sc = a.get('scene') if a.get('scene') in ['sunny','partlycloudy','cloudy','rainy','pouring','storm','snowy','sleet','fog','windy'] else 'cloudy' %}
    {% set d = a.get('daytime') if a.get('daytime') in [true, false] else is_state('sun.sun', 'above_horizon') %}
    ha-card {
      background-image: linear-gradient(180deg, rgba(0,0,0,.42) 0%, rgba(0,0,0,.12) 38%, rgba(0,0,0,.18) 55%, rgba(0,0,0,.62) 100%), url('/local/zizkov/{{ sc }}-{{ 'day' if d else 'night' }}.jpg?v=2') !important;
      background-size: cover !important;
      background-position: center !important;
      --primary-text-color: #fff;
      --secondary-text-color: rgba(255,255,255,.88);
      color: #fff;
      text-shadow: 0 1px 4px rgba(0,0,0,.75);
    }
```
